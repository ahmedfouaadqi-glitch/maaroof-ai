# MAAROOF AI — التنفيذ التدريجي دون الاعتماد على Cloudflare

## حدود السلامة الحالية

- لا تُضاف أو تُنشأ Cloudflare Queues أو Workers أو Bindings.
- لا يجري تعديل `wrangler.jsonc` أو إعدادات النشر، ولا يتم أي نشر.
- لا تُطبق ترحيلات على قاعدة بيانات المشروع الحية.
- لا تتغير تكاملات مزودي النماذج الحالية أو أسماء النماذج أو المصادقة أو نقاط النهاية أو التوجيه.
- لا يُدمج فرع التطوير المتباعد مباشرة؛ العمل يجري في فرع مستقل من أحدث `main`.

## ما يتضمنه هذا التغيير

### 1. محرك المقابلات
- وظائف TypeScript نقية لا تعتمد على قاعدة بيانات أو مزود أو runtime.
- أنواع سياق للفرد وصانع المحتوى والشركة والوكالة والعميل والعلامة والمشروع والمهمة.
- مسارات عامة وSEO وAEO وGEO وGSEO.
- ترتيب السؤال التالي، والتفرع حسب الإجابات، وتسجيل الإجابة أو التخطي أو عدم المعرفة، وإحصاءات التقدم.
- التحقق من لقطات الأسئلة: معرفات فريدة، ترجمات ar/en/ku، قيم وسياسات صحيحة، مراجع موجودة، ومنع التبعيات الدائرية.

### 2. بنك أسئلة أساسي
- بنك مركزي متعدد اللغات، يتم اختياره حسب نوع الكيان ومسارات العمل.
- الأسئلة العامة وأسئلة النوع المحدد وأسئلة كل مسار منفصلة، لتجنب الأسئلة غير ذات الصلة.
- رقم إصدار لبنك الأسئلة؛ تحفظ الجلسة لقطة الأسئلة حتى لا يتغير معنى مقابلة بدأت سابقاً عند تحديث البنك.

### 3. حفظ جلسات المقابلة
- ترحيل SQL يضيف `public.maaroof_interviews` مع سياق الجلسة وحالتها والإجابات ولقطة الأسئلة والإصدار.
- نقطة API لإنشاء الجلسة وقراءتها واستئنافها وحفظ الإجابات وتحديث الحالة.
- التحقق من هوية المستخدم، وملكية مساحة العمل، ودور العضو (المالك والمحرر للكتابة، والمشاهد للقراءة).
- تعيّن الواجهة البرمجية مصدر الإجابة إلى المستخدم؛ لا يمكن للعميل تزوير أن الإجابة تم التحقق منها خارجياً.
- تحديثات بإصدار متوقع (`version`) لمنع طلب متزامن من الكتابة فوق إجابة أحدث.
- سياسات RLS للقراءة، مع حصر الكتابة في مسار الخادم الذي يتحقق من الصلاحيات.

## ملاحظات تشغيلية مهمة

- ترحيل `20261017170000_maaroof_interviews.sql` موجود في الفرع فقط ولم يُطبّق على Supabase.
- نقطة API لن تكون قابلة للتشغيل حتى يُطبّق الترحيل في بيئة اختبار وتُختبر صلاحيات القراءة والكتابة والاستئناف والتزامن فعلياً.
- واجهة `/workspace` لم تُربط بعد بهذا الـAPI؛ ذلك يأتي بعد التحقق من الطبقة الخلفية.
- محرك المقابلات وبنك الأسئلة لا يثبتان صحة حقيقة خارجية؛ إثراء الملف يحتاج طبقة منفصلة تحفظ المصدر والتاريخ ومستوى الثقة.
- استمرار المهام الطويلة بعد إغلاق المتصفح لم يُنفذ أو يثبت في هذا التغيير. سيُدرس خيار المعالجة الخلفية خارج Cloudflare على حدة؛ لا يُعتمد Supabase Queues قبل اختبار حدود التنفيذ والتكلفة ونمط تشغيل معروف.

## التحقق الآلي

- في الالتزام `dca67c6461e0f8ad971c56e028eb43231032cbc6` نجحت اختبارات المحرك الـ12 وفحص ESLint وفحص TypeScript للمشروع عبر GitHub Actions.
- في الالتزام `433710a44ff8d7ce3a1a1ad424335a63e33c1a1c` نجحت 16 من اختبارات محرك المقابلات و4 اختبارات بنك الأسئلة؛ أوقف ESLint التنفيذ بسبب مشكلة تنسيق واحدة في شرط إكمال الجلسة، وتم تصحيحها قبل إعادة الاختبار.
- اختبارات بنك الأسئلة الـ4 نجحت أيضاً في تشغيله الأخير، لكن فحص ESLint للطبقة الجديدة أوقف التشغيل بسبب التنسيق؛ جرى تطبيق منسق المشروع تلقائياً، ويجب اعتماد نتيجة CI على الالتزام النهائي بعد إزالة مسار التنسيق المؤقت.

## بوابات القبول التالية

1. تشغيل اختبارات بنك الأسئلة والمحرك، وESLint وTypeScript بعد إضافة API.
2. مراجعة ترحيل SQL وسياسات RLS قبل تطبيقه على بيئة اختبار.
3. اختبار API مع المستخدمين وعضوية مساحة العمل والأدوار، بما في ذلك الرفض الآمن.
4. اختبار إصدار الجلسة والطلبات المتزامنة واستئناف الجلسة بعد إعادة تحميل الصفحة.
5. ربط واجهة العمل بالمقابلات، ثم إضافة إثراء السياق من مصادر موثقة.
6. تقييم نظام مهام خلفية خارج Cloudflare، واختبار التنفيذ الطويل والتعافي والإلغاء والخصم قبل اعتماد التشغيل.
7. تطوير موجّه المحركات العشرة دون المساس بالتكاملات الأصلية، ثم مسارات SEO/AEO/GEO/GSEO والتقارير والتصدير والواجهة.
