# MAAROOF AI — التنفيذ التدريجي دون الاعتماد على Cloudflare

## حدود السلامة الحالية

- لا تُضاف أو تُنشأ Cloudflare Queues أو Workers أو Bindings.
- لا يجري تعديل `wrangler.jsonc` أو إعدادات النشر، ولا يتم أي نشر.
- لا تُطبق ترحيلات على قاعدة بيانات المشروع الحية.
- لا تتغير تكاملات مزودي النماذج الحالية أو أسماء النماذج أو المصادقة أو نقاط النهاية أو التوجيه.
- لا يُدمج فرع التطوير المتباعد مباشرة؛ العمل يجري في فرع مستقل من أحدث `main`.

## ما يتضمنه هذا التغيير

### 1. محرك المقابلات
- وظائف TypeScript نقية لا تعتمد على قاعدة بيانات أو مزود أو runtime.
- أنواع سياق للفرد وصانع المحتوى والشركة والوكالة والعميل والعلامة والمشروع والمهمة.
- مسارات عامة وSEO وAEO وGEO وGSEO.
- ترتيب السؤال التالي، والتفرع حسب الإجابات، وتسجيل الإجابة أو التخطي أو عدم المعرفة، وإحصاءات التقدم.
- التحقق من لقطات الأسئلة: معرفات فريدة، ترجمات ar/en/ku، قيم وسياسات صحيحة، مراجع موجودة، ومنع التبعيات الدائرية.

### 2. بنك أسئلة أساسي
- بنك مركزي متعدد اللغات، يتم اختياره حسب نوع الكيان ومسارات العمل.
- الأسئلة العامة وأسئلة النوع المحدد وأسئلة كل مسار منفصلة، لتجنب الأسئلة غير ذات الصلة.
- رقم إصدار لبنك الأسئلة؛ تحفظ الجلسة لقطة الأسئلة حتى لا يتغير معنى مقابلة بدأت سابقاً عند تحديث البنك.

### 3. واجهة المقابلات وربط مساحة العمل

- إضافة `InterviewPanel` إلى `/workspace` مع اختيار نوع الجهة ومجالات العمل، وعرض السؤال الحالي فقط، وخيارات التخطي أو تسجيل «لا أعرف» وفق سياسة السؤال.
- اختيار مساحة عمل يملكها المستخدم أو لديه صلاحية تحرير فيها، أو حفظ المقابلة في الحساب الشخصي.
- قائمة للجلسات المحفوظة، وإمكانية فتحها واستئنافها، وشريط تقدم وسجل للإجابات السابقة.
- ترجمة الواجهة إلى العربية والإنجليزية والكردية؛ لغة المقابلة ترث لغة الواجهة في هذه المرحلة.

### 4. حفظ جلسات المقابلة
- ترحيل SQL يضيف `public.maaroof_interviews` مع سياق الجلسة وحالتها والإجابات ولقطة الأسئلة والإصدار.
- نقطة API لإنشاء الجلسة وقراءتها واستئنافها وحفظ الإجابات وتحديث الحالة.
- التحقق من هوية المستخدم، وملكية مساحة العمل، ودور العضو (المالك والمحرر للكتابة، والمشاهد للقراءة).
- تعيّن الواجهة البرمجية مصدر الإجابة إلى المستخدم؛ لا يمكن للعميل تزوير أن الإجابة تم التحقق منها خارجياً.
- تحديثات بإصدار متوقع (`version`) لمنع طلب متزامن من الكتابة فوق إجابة أحدث.
- يستخدم عميل Supabase الإداري نوع `Database` الموجود بالمشروع؛ وجداول المقابلات الجديدة تُعالَج عبر طبقة خادم موثقة مؤقتاً إلى أن يُحدّث توليد الأنواع بعد تطبيق الترحيل في بيئة اختبار.
- سياسات RLS للقراءة، مع حصر الكتابة في مسار الخادم الذي يتحقق من الصلاحيات.

## ملاحظات تشغيلية مهمة

- ترحيل `20261017170000_maaroof_interviews.sql` موجود في الفرع فقط ولم يُطبّق على Supabase.
- نقطة API لن تكون قابلة للتشغيل حتى يُطبّق الترحيل في بيئة اختبار وتُختبر صلاحيات القراءة والكتابة والاستئناف والتزامن فعلياً.
- واجهة `/workspace` أُضيف إليها مكون المقابلات في فرع المسودة؛ لم تُختبر بعد مع قاعدة بيانات فعلية، لذلك يبقى اختبار الحفظ والاستئناف وتفويض مساحة العمل مشروطاً بتطبيق الترحيل في بيئة اختبار.
- محرك المقابلات وبنك الأسئلة لا يثبتان صحة حقيقة خارجية؛ إثراء الملف يحتاج طبقة منفصلة تحفظ المصدر والتاريخ ومستوى الثقة.
- استمرار المهام الطويلة بعد إغلاق المتصفح لم يُنفذ أو يثبت في هذا التغيير. سيُدرس خيار المعالجة الخلفية خارج Cloudflare على حدة؛ لا يُعتمد Supabase Queues قبل اختبار حدود التنفيذ والتكلفة ونمط تشغيل معروف.

## التحقق الآلي

- في مراجعة PR عند الالتزام `697e876c3524b3076cd19f8e3a3fcffd08d0c7e2` نجحت اختبارات محرك المقابلة وبنك الأسئلة، وعددها 20 اختباراً، وفحص ESLint وفحص TypeScript الكامل.
- كشف فحص أسبق خطأ TypeScript في تضييق نوع استجابة استئناف الجلسة؛ أضيف تحقق صريح قبل تمرير المقابلة إلى الحالة.
- بوابة التحقق المطلوبة لكل نسخة هي نجاح الاختبارات وESLint وTypeScript وبناء الإنتاج على **الرأس الدقيق نفسه**. نتيجة قديمة لا تثبت سلامة تعديلات أحدث، بما فيها قواعد RLS أو واجهة/API.
- أزيل سير العمل المؤقت الذي كان يشغّل ESLint مع `--fix` ويدفع التعديلات آلياً بصلاحية كتابة. لا يُستخدم مسار تصحيح تلقائي يكتب إلى الفرع.

## بوابات القبول التالية

1. نجاح CI على الرأس النهائي للفرع: اختبارات المحرك وبنك الأسئلة، وESLint، وTypeScript، وبناء الإنتاج.
2. مراجعة ترحيل SQL ثم تطبيقه في بيئة Supabase اختبارية؛ التحقق من عزل المستخدم الشخصي والمالك والأعضاء والمشاهد والمحرر بسياسات RLS.
3. اختبار API لإنشاء الجلسة وإجابة السؤال الحالي فقط، والتوقف والاستئناف والإكمال، ورفض الإجابة على جلسة متوقفة، ورفض الوصول غير المخوّل.
4. اختبار التزامن وإعادة تحميل الصفحة والاستئناف مع تحقق الإصدار المتوقع، وتغطية أخطاء الاتصال والبيانات المخزنة غير الصالحة.
5. إضافة إثراء السياق من مصادر موثّقة، مع مصدر وتاريخ رصد ومستوى ثقة وموافقة المستخدم وحق التعديل والحذف؛ لا تُعرض الاستنتاجات كحقائق مؤكدة.
6. دراسة وتنفيذ المهام الخلفية خارج Cloudflare بعد اختبار فعلي للاستمرار بعد إغلاق المتصفح، والتعافي والإلغاء والخصم والتكلفة؛ لا يُعلن استمرار التنفيذ قبل إثباته.
7. بناء مسارات SEO/AEO/GEO/GSEO والتقارير والتصدير تدريجياً مع فصل المقاييس والأدلة والمصادر وعدم المساس بتكاملات مزودي النماذج الحالية.
