# MAAROOF AI — تنفيذ تدريجي دون اعتماد جديد على Cloudflare

## قرار نطاق العمل

- لا تُضاف حالياً Cloudflare Queues أو Workers أو Bindings جديدة.
- لا يُعدّل `wrangler.jsonc` ولا إعداد النشر أو تكاملات مزودي النماذج في هذه المرحلة.
- لا يُدمج فرع التطوير القديم مباشرة؛ تتم إعادة تطبيق التغييرات المطلوبة فوق أحدث `main`.
- لا يُعلن أن المهام الخلفية تستمر بعد إغلاق المتصفح لمجرد حفظ سجل المهمة.

## ملاحظات مؤكدة من مراجعة الكود على `main`

1. مسار `src/routes/api/maaroof.ts` ينشئ سجلاً في `maaroof_jobs` عند `interface_mode === "workspace"` ثم يشغّل `runMaaroof` عبر `runAfterResponse(work)`. هذا وحده لا يثبت متانة التنفيذ بعد انتهاء عمر عملية الطلب أو تعطلها.
2. مسار `src/routes/api/maaroof-jobs.ts` يعرض السجلات والأحداث ويتيح الإلغاء؛ لذلك يجب مراجعة ضمانات التزامن والإلغاء وملكية السجلات قبل توسيعه.
3. كتالوج المحركات العشرة يحتوي على ستة تعريفات تستخدم `proxy: true` إلى جانب ChatGPT وGemini، لكن اسم المحرك الظاهر لا يثبت وحده أن اتصالاً مباشراً بالمزود قد حدث. يجب حفظ مصدر التنفيذ الفعلي وإظهار البدائل بوضوح.
4. `src/lib/maaroof/agent-input.ts` لديه أسئلة توضيحية على مستوى حقول الأدوات، لكنه لا يقدم بعدُ محرك مقابلات عامّاً يدير السياق والتفرع وحالة المقابلة عبر المستخدمين والعملاء والعلامات والمشاريع والمهام.

## الترتيب التنفيذي

### A — أساس المقابلات المستقل عن البنية التحتية
- بناء أنواع سياق مشتركة للفرد، وصانع المحتوى، والشركة، والوكالة، والعميل، والعلامة، والمشروع، والمهمة.
- بناء منطق أسئلة نقي (pure functions): الملاءمة بحسب السياق والمسار، أسئلة مشروطة، سؤال واحد في كل مرة، إجابات ومصادرها، وحالة التقدم.
- اختبارات وحدات قبل ربط المنطق بواجهة أو قاعدة بيانات.
- حفظ المخرجات في طبقة تخزين منفصلة لاحقاً؛ يمنع وضع منطق قاعدة البيانات داخل محرك المقابلات.

### B — نموذج البيانات والتخزين
- تحديد ملكية سجل المقابلة وارتباطه بالكيان الصحيح، وسياسات العزل.
- الاحتفاظ بإصدارات الأسئلة وإجاباتها ومصدرها وتوقيتها، مع دعم التصحيح والحذف والاستئناف.
- لا يُطبّق ترحيل على قاعدة البيانات المتصلة حتى تُراجع سياسة الملكية وRLS وخطة الرجوع.

### C — الوظائف الخلفية من دون Cloudflare
- الخيار المرشح للدراسة: Supabase Queues المبنية على `pgmq`، مع Supabase Cron لاستدعاء عامل معالجة مناسب؛ يجب التحقق من إتاحة الامتدادات وإعدادات المشروع وحدود زمن التنفيذ وقدرة العامل على استدعاء المنظومة الحالية قبل اعتماد القرار.
- الوثائق الرسمية: [Supabase Queues](https://supabase.com/docs/guides/queues) و[Supabase Cron](https://supabase.com/docs/guides/cron) و[Scheduling Edge Functions](https://supabase.com/docs/guides/functions/schedule-functions).
- يجب الفصل بين سجل المهمة ورسالة الطابور، واستخدام idempotency key، وقفل/lease للمطالبة بالمهمة، ومحاولات محدودة، وحالة فشل نهائي قابلة للتشخيص، وسجل أحداث متسلسل.
- إذا لم يثبت أن عامل Supabase مناسب لطول مهام معروف أو لطريقة استدعاء أدواته الداخلية، يتوقف هذا الجزء عند التصميم ولا يُدَّعى أنه يعمل. لا يُستبدل Cloudflare بخدمة أخرى قبل اختبارها.

### D — السياق المؤسسي والمقابلات
- الحساب ← المؤسسة/الوكالة ← العملاء والعلامات ← المشاريع ← المقابلات والمهام والتقارير.
- المقابلة تسند دائماً إلى هدف محدد ومالك واضح؛ لا تنقل حقائق العميل إلى الوكالة أو العلامة الأخرى.
- لا تُحوَّل التقديرات أو بيانات المصادر الخارجية إلى حقائق مصرّح بها.

### E — موجّه المحركات العشرة
- عدم تغيير الاتصال الحالي أو أسماء النماذج أو المصادقة أو نقاط النهاية ضمن هذه المرحلة.
- إضافة سجل قدرات وحالة تكامل، ثم أوضاع Auto/Compare/Verify فوق الاتصالات الحالية.
- توثيق مباشر مقابل proxy/stand-in، وعدم إظهار علامة المحرك بوصفها منفذاً إلا إذا كان ذلك مثبتاً في سجل التنفيذ.

### F — SEO / AEO / GEO / GSEO والتقارير واللغات والواجهة
- مسارات ومقاييس منفصلة لكل مجال؛ لا درجة موحدة مبهمة.
- عقد نتائج موحد يحفظ findings وmetrics وsources وevidence وrecommendations وexecution والمخرجات الخام.
- لغة الواجهة مستقلة عن لغة المهمة وعن لغة التصدير.
- تحسين واجهة مساحة العمل والحركة بعد ثبوت صحة تدفق البيانات والصلاحيات.

### G — بوابات القبول
لا تُدمج المرحلة أو تُطلق قبل:
- اختبارات الوحدات وفحوصات TypeScript وlint والبناء ذات الصلة.
- اختبار عزل بيانات المستخدمين والعملاء والصلاحيات من الخادم.
- اختبار المقابلات الشرطية والحفظ والاستئناف وتصحيح الإجابة.
- اختبار إعادة المحاولة والإلغاء ومنع الخصم المزدوج للمهام الخلفية.
- اختبار صحة إسناد النتيجة إلى المحرك والأداة والمصدر الحقيقيين.
- اختبار اللغات والتصدير وRTL/LTR.

## ما أُنجز في خطوة التأسيس الحالية

- إنشاء فرع تطوير جديد مبني على أحدث `main` بدل مواصلة فرع متباعد.
- إضافة محرك مقابلات نقي قابل للاختبار، من دون اتصال بقاعدة بيانات أو مزود أو منصة نشر.
- إضافة اختبارات تغطي ترتيب الأسئلة، السياق، التفرع، التخطي، "لا أعرف"، التحقق من الإجابات والتقدم.
- عدم تغيير مسار التشغيل الحالي أو تطبيق ترحيلات قاعدة البيانات أو نشر المشروع.

هذه الخطوة تأسيسية ولا تعني بعدُ أن واجهة المقابلات أو الحفظ الدائم أو الوظائف الخلفية أصبحت متصلة ومفعّلة.
