# خطة دمج منظومة التقارير التنفيذية وتفعيلها

## المرحلة 1: دمج الكود المعتمد
- جلب ملفات الفرع `feat/non-destructive-owner-workspaces-reports-2026-11-17` فقط: `src/lib/reports/*`، واجهة مركز التقارير، واختباراتها.
- عدم لمس الملفات المحمية (المحركات العشرة، المجلس، فحص الظهور، حراس مساحات العمل، الخصم).
- تشغيل كل الاختبارات والتأكد من نجاح البناء.

## المرحلة 2: طبقة الحفظ السحابية
- جداول جديدة: `reports` (التقرير، الدرجات، الأدلة، مساحة العمل)، `report_branding` (شعار وألوان وبيانات تواصل لكل مساحة)، `report_share_grants` (رمز مشاركة مشفّر، تاريخ انتهاء، إلغاء).
- صلاحيات صارمة: كل تقرير مقيّد بمالكه ومساحة عمله، ولا يظهر في الحساب الأساسي أو مساحة أخرى.

## المرحلة 3: رابط المشاركة للعميل
- صفحة عامة `/reports/share/$token` تعرض التقرير التنفيذي (بروح نموذج shop_and_beyond) دون تسجيل دخول.
- التحقق من الرمز وصلاحيته في الخادم، وعرض حقول التقرير الآمنة فقط، مع `noindex`.

## المرحلة 4: ربط الواجهة
- زر «مركز التقارير» في مساحة العمل.
- خيار «حفظ كتقرير تنفيذي» بجانب أزرار التصدير الحالية بعد أي فحص أو مهمة.
- اختبار التدفق كاملاً: فحص ← حفظ ← معاينة ← رابط مشاركة ← فتح كعميل.

## الضوابط
- لا خصم رصيد لإنشاء التقرير أو مشاركته (يُعرض ناتج أداة سبق خصمها).
- لا قيم مختلقة: الحقل بلا دليل يظهر «لم يُقَس» مع السبب.
- لا نشر دون موافقتك الصريحة.

## تفاصيل تقنية
- قراءة الرابط العام عبر دالة خادم بعميل عام ودالة قاعدة بيانات آمنة تُرجع التقرير بالرمز فقط.
- دوال الحفظ والإدارة محمية بالمصادقة و workspaceGuard.
- اختبارات جديدة: عزل المساحات، انتهاء/إلغاء الرابط، عدم وجود خصم.
