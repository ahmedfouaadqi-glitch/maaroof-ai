# خطة تطوير الوكيل: عرض واضح، تصدير انتقائي، وثيقة احترافية

مبدأ ثابت: نطوّر الموجود فقط، لا نعيد بناء ولا نكرر ولا نعطل. لا نشر دون موافقة صريحة. لا JSON خام أمام المستخدم.

## 1. المشكلة الفعلية (من ملف PDF المرفق)
- التصدير الحالي (`buildReport` في `src/routes/maaroof.tsx`) يضع كائنات JSON داخل خلايا جداول فتتمزق الحروف (8 صفحات مشوهة).
- بطاقة كل أداة في `MaaroofStage.tsx` لا تعرض "الإجابة المباشرة"؛ فقط حالة نجاح وزر نماذج.
- مجلس الخبراء، نقاش النماذج العشرة، والتأمل الذاتي موجودة في الخلفية لكنها غير ظاهرة ولا مصدّرة.

## 2. المراحل (بالترتيب)

### المرحلة 1: تصدير نظيف وانتقائي (الأولوية القصوى)
- ملف جديد نقي `src/lib/maaroof/report-sections.ts`: يحوّل ناتج كل أداة إلى أقسام مقروءة (`kv/text/table/list`) عبر `sectionsFromResult` الموجود في `export-bus.ts`، مع إسقاط المفاتيح التقنية وتسطيح القيم المتداخلة إلى نص.
- `buildReport()`: غلاف + ملخص تنفيذي + قسم لكل أداة + ما فعله كل وكيل فرعي + نقاش النماذج العشرة + التأملات + الكلفة. التفاصيل التقنية قسم اختياري في الأوضاع الثلاثة (توصية، محاكاة، تنفيذ).
- نافذة تصدير: اختيار الكل / أداة معينة / وكيل معين، ومفتاح "تضمين التفاصيل التقنية". صيغ PDF و Excel و JSON عبر `ExportButtons` الحالي.
- أبعاد الصفحة تتناسب مع المحتوى (A4 للتقرير، أعمدة جداول بعروض محسوبة، نص التقني LTR بخط ثابت العرض).
- اختبارات وحدة: لا يوجد `{` أو `[object` في الأقسام الناتجة.

### المرحلة 2: عرض الإجابة المباشرة بحركة منظمة
- `MaaroofStage.tsx`: في كل بطاقة أداة، "الإجابة المباشرة" في سطر أو سطرين (مستخرجة بدالة نقية) ثم زر "التفاصيل". دخول البطاقات بتدرج حركي خفيف (CSS/Reveal الموجود) مع احترام `prefers-reduced-motion`.
- عرض وكيل التخصص `specialist:<tool>` على البطاقة، وزر "تصدير هذه الإجابة".
- لوحة "كيف وصلنا": خطوات الوكلاء، مجلس الخبراء، النقد الذاتي، نقاش النماذج العشرة عبر `cardsForStep` و`EngineResponseFlow` الموجودين.
- مثال توضيحي متغير لكل إجابة يُولَّد من بيانات الجلسة نفسها (اسم العلامة، الدولة، الأرقام) لا نصاً ثابتاً.

### المرحلة 3: ربط ما هو مدفون في الخلفية بالمسرح
- إصدار أحداث إضافية للمسرح من `orchestrator.server.ts` من بيانات موجودة أصلاً (آراء الخبراء، التعارض، الامتثال، نتيجة فحص الكيان) دون استدعاءات نموذج جديدة.
- Firecrawl يبقى خلفياً ولا يظهر للمستخدم؛ يظهر فقط كسؤال استيضاحي.

### المرحلة 4: تقليل الكلفة والتوثيق
- إعادة استخدام MCI قبل أي استدعاء، والفحص المحلي الحتمي أولاً؛ كل إضافة في المرحلتين 1-3 بلا استدعاء نموذج جديد.
- إضافة سطر ملكية `Architecture & Concept: Ahmed Maaroof` كتعليق في رؤوس الملفات الأساسية وحقل `author` في `package.json` (توثيق مشروع عادي، وليس إخفاء مضللاً).

## 3. تفاصيل تقنية
- الملفات: `src/routes/maaroof.tsx`، `src/components/maaroof/MaaroofStage.tsx`، `src/lib/exports.ts`، `src/lib/export-bus.ts`، `src/lib/maaroof/report-sections.ts` (جديد، نقي)، `src/lib/maaroof/orchestrator.server.ts` (أحداث فقط).
- بدون تغيير في منطق الأدوات أو الأسعار أو قاعدة البيانات.
- بعد كل مرحلة: فحص الأنواع + الاختبارات (46 حالياً) ثم تقرير موجز.

## 4. خارج النطاق
- لا نشر، لا تغيير تسعير، لا بناء عمليات جديدة. الأسئلة الوجودية/الإيمانية ليست جزءاً من النظام؛ الإثبات التقني يتم عبر سجلات الشبكة والكلفة المعروضة.
