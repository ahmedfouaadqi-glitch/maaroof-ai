# خطة: تطوير الموجود — الإصلاح الفوري، الفحص المصغّر باختيار النماذج، ربط الرصيد وأنماط التشغيل، وتحديث الدليلين

الشروط الصارمة: تطوير لما هو موجود ومتوفر — لا إضافة أنظمة موازية، لا إعادة بناء، لا إعادة تسمية، لا حذف، لا تكرار، ولا تغيير لمنطق أي أداة. أي خطأ في التطوير يُعيد الأداة لسلوكها الحالي. لا نشر قبل موافقتك.

## 1) الإصلاح الفوري (تطوير أداة التحليل وبطاقة السلطة الحاليتين)
- داخل نتيجة التحليل الحالية: زر «أصلح ليتوافق مع GEO» يستخدم أداة إعادة الصياغة الموجودة (GEO Rewrite) على أول 120–150 كلمة، دون اختلاق أرقام.
- زر «ولّد ملفات قراءة الآلة» يستخدم بطاقة سلطة العلامة الموجودة لإنتاج llms.txt و JSON-LD جاهزة للنسخ.
- الخصم عبر نظام الرصيد الحالي وبسعر الأداة الأصلية.

## 2) الفحص المصغّر باختيار النماذج (تطوير فحص الظهور الحالي)
- فحص الظهور يسأل النماذج فعلاً اليوم؛ نطوّره ليُستدعى من أي أداة بعد التقدير الخوارزمي.
- المستخدم يختار كل النماذج التسعة أو عدداً محدداً بالضغط على الشعارات؛ المقفلة حسب الباقة تظهر مقفلة.
- قبل التشغيل: الكلفة المتوقعة حسب عدد النماذج المختارة والرصيد المتبقي؛ يُعطّل الزر إذا لم يكفِ.
- النتيجة في بطاقات النماذج الحالية بوسم «إجابة فعلية» بجانب التقدير، مع الفارق.

## 3) الرصيد مرتبط بكل الأدوات (تطوير نظام الخصم الحالي)
- كل أداة وعملية فرعية (فحص مصغّر، إصلاح، توليد ملفات، تحديث إجباري) تمر بنظام الخصم نفسه.
- عرض «الكلفة المتوقعة / رصيدك» قبل التشغيل في شريط الرصيد الموجود.
- الأداة غير المسعّرة تبقى كما اليوم، وتظهر في كاشف فجوات التسعير.

## 4) أنماط التشغيل (تطوير الجدولة والإشعارات الحالية)
- **فوري** كما اليوم، **في الخلفية** (النتيجة تُحفظ في سجل الأداة الحالي)، **إشعاري** (عبر صندوق الإشعارات الحالي، والبريد اختيارياً)، **تلقائي مجدول** عبر جدولة معروف الموجودة للأدوات القابلة للتكرار، مع خصم لكل تشغيل وإيقاف تلقائي عند نفاد الرصيد.

## 5) تحكم الإدارة (تطوير لوحة التوكنز ومصفوفة الخطط الحاليتين)
- لكل أداة: السعر، التفعيل، الأنماط المسموحة، سعر كل نموذج في الفحص المصغّر، الحد الأقصى للنماذج.
- لكل مستخدم: تجاوز أي قيمة لكل أداة، حد يومي/شهري خاص بالأداة، إيقاف المجدول.
- عرض استهلاك كل مستخدم لكل أداة ولكل عملية فرعية في سجل الاستهلاك الحالي.

## 6) تحديث دليل المستخدم ودليل الإدارة (ثلاثي اللغة)
- **دليل المستخدم:** يرى كل مستخدم ما يخصه فقط، حسب نوعه: فرد، شركة، صانع محتوى، صاحب متجر، صاحب منتج. لكل نوع: الأدوات المفيدة له، الإصلاح الفوري، الفحص المصغّر واختيار النماذج، الرصيد والكلفة، أنماط التشغيل — مع أمثلة عملية (مثال: صاحب متجر يفحص «أفضل متجر عطور في بغداد» على 3 نماذج بكلفة محددة).
- **دليل الإدارة:** كل الإعدادات الجديدة بالتفصيل مع أمثلة (مثال: جعل الفحص المصغّر 50 توكن لكل نموذج، أو منع المجدول لمستخدم معيّن، أو رفع حد أداة لشركة).

## ترتيب التنفيذ
1. توسيع إعدادات التسعير والأنماط في الإدارة + عرض الكلفة.
2. الفحص المصغّر باختيار النماذج.
3. الإصلاح الفوري وملفات قراءة الآلة.
4. أنماط الخلفية/الإشعاري/المجدول.
5. تحديث الدليلين.
6. اختبارات + فحص في المتصفح.

## تفاصيل تقنية
- إعادة استخدام `resolveToolCost` / `chargeTokens` / `charge_tokens`: عمليات فرعية بمفاتيح `analyze.fix`, `analyze.machine_files`, `visibility.probe` (tokens × عدد النماذج، أسماؤها في meta).
- الفحص المصغّر عبر `/api/visibility` الحالي بمعامل اختياري `engines` يمر بـ `applyEntitlement` — المعامل غائب = السلوك الحالي.

- الخلفية/الإشعار: `report_drafts` + `user_notifications`؛ المجدول: `maaroof_schedules`. لا جداول جديدة.
- الواجهة: تطوير `AIVisibility`, `Sandbox`, `TokensBar`, `EngineSelector`, `AdminTokensPanel`, `AdminPlansMatrixPanel`, `ToolHistory`, `SchedulesPanel`.
