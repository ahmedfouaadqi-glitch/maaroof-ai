# ربط قنوات النشر لكل مستخدم — شخصي / مؤسسة / براند

## الوضع الحالي (تم التحقق منه)

- **تيليجرام**: ربط شخصي حقيقي يعمل عبر رابط البوت ورمز مؤقت — نُبقيه ونُبسّطه.
- **لينكدإن**: الزر الحالي لا يربط حساب المستخدم إطلاقاً. ينشئ قناة وهمية باسم «حساب مشترك» ويُنشر عبر حساب واحد على مستوى المنصة (`LINKEDIN_API_KEY`). هذا سلوك خاطئ ويجب استبداله.
- **فيسبوك / إنستغرام / X**: المستخدم مُطالب بفتح بوابة مطوّرين ونسخ توكن يدوياً ولصقه — أصعب خطوة في المنتج، ومعدل نجاحها منخفض بطبيعتها.
- **التوكنات مخزّنة كنص صريح** في عمود `publish_channels.config`، ومقروءة من مسار الخدمة. يجب تشفيرها.
- الكود الحالي يفترض **قناة واحدة لكل منصة** لكل مستخدم (`maybeSingle`)، لذا تعدد الحسابات يحتاج تعديل مسارات القراءة أيضاً.

## ما سنبنيه

### 1) ربط بضغطة واحدة (OAuth) لكل مستخدم

تطبيق مطوّر واحد باسم «معروف» لكل منصة يسجّله فريقك، ثم كل مستخدم يوافق على حسابه بنفسه:

- **لينكدإن**: حساب شخصي + صفحات الشركات التي يديرها المستخدم.
- **Meta**: تطبيق واحد يغطي صفحات فيسبوك وحسابات إنستغرام للأعمال.
- **X (تويتر)**: حساب شخصي.

التدفق للمستخدم:

```text
[ربط لينكدإن]  →  نافذة موافقة المنصة  →  عودة تلقائية
        →  «اختر الحساب»: شخصي | صفحة الشركة | صفحة البراند
        →  ✓ مربوط
```

- تُفتح الموافقة في نافذة منبثقة (لا تعمل داخل إطار المعاينة بغير ذلك).
- بعد الموافقة نجلب قائمة الحسابات/الصفحات المتاحة ونعرضها للاختيار — لا يُطلب من المستخدم أي معرّف أو توكن.
- المستخدم يمكنه ربط أكثر من حساب لنفس المنصة، وكل قناة تحمل **وسم النوع**: شخصي / مؤسسة / براند راعٍ. وسم البراند يقبل اسم الجهة الراعية.
- عند النشر يختار المستخدم القناة الهدف، والوسم يظهر بجانب الاسم.

### 2) تبسيط الإجراءات

- بطاقة واحدة لكل منصة: زر «ربط» أو حالة «✓ مربوط» + قائمة الحسابات المربوطة.
- إخفاء «اللصق اليدوي للتوكن» داخل قسم **«إعداد متقدّم»** مطوي، يبقى كخيار احتياطي فقط.
- تعطيل زر الربط تلقائياً مع رسالة «قيد إعداد الإدارة» لأي منصة لم تُضاف مفاتيحها بعد.
- زر «تجربة النشر» لكل قناة للتأكد من صلاحيتها قبل أول منشور حقيقي.

### 3) الدليل

- **داخل الشاشة**: 3 خطوات مختصرة أعلى تبويب القنوات + سطر مساعدة داخل كل بطاقة + ملاحظة متطلبات (إنستغرام يحتاج حساب أعمال، النشر كصفحة يحتاج صلاحية إدارة).
- **صفحة `/guide`**: قسم كامل ثلاثي اللغة (عربي / إنجليزي / كردي) يشرح أنواع الحسابات، خطوات الربط لكل منصة، الأخطاء الشائعة، وكيفية الفصل والاسترجاع.

## التفاصيل التقنية

**قاعدة البيانات** (ترحيل واحد):
- إضافة إلى `publish_channels`: `owner_type` (`personal` | `organization` | `brand`)، `owner_name`، `is_default`، `token_ciphertext`، `token_expires_at`، `last_verified_at`، `last_error`.
- نقل التوكنات إلى تشفير AES-256-GCM داخل مسار الخدمة، وإفراغ الأسرار من `config`.
- فهرس يسمح بعدة قنوات لكل (مستخدم، منصة) مع قناة افتراضية واحدة لكل منصة.
- جدول قصير الأجل لحالات OAuth (state) لمنع تمرير الحالة عبر المتصفح.

**المسارات والدوال**:
- مسارات `src/routes/api/oauth/<provider>/callback.ts` لتبادل الكود مقابل توكن، مع `state` موقّع ومربوط بالمستخدم.
- دوال خادم جديدة في `publish.functions.ts`: بدء الربط، جلب الحسابات المتاحة، تثبيت القناة المختارة، تجربة النشر، الفصل.
- تحديث كل مسارات القراءة التي تفترض قناة واحدة (`publish.functions.ts`، `agent.functions.ts`، `maaroof/publishing.server.ts`، `notify.server.ts`) لتعمل مع القناة الافتراضية أو القناة المحددة.
- فك التشفير يحدث فقط لحظة النشر داخل الخادم؛ لا توكن يصل المتصفح أبداً.
- تحديث `publishToLinkedIn` لتنشر بتوكن المستخدم بدل حساب المنصة المشترك، ودعم النشر كصفحة شركة.

**الأسرار المطلوبة منك** (تُطلب بنموذج آمن بعد الموافقة على الخطة):
`LINKEDIN_CLIENT_ID` / `LINKEDIN_CLIENT_SECRET` — `META_APP_ID` / `META_APP_SECRET` — `X_CLIENT_ID` / `X_CLIENT_SECRET`. ومفتاح التشفير يُنشأ تلقائياً.
سأزوّدك بعنوان الـ Redirect URI الواحد لكل منصة لتضعه في لوحة المطوّر قبل طلب المفاتيح.

## الترتيب

1. الترحيل + طبقة التشفير + توحيد قراءة القنوات (يعمل فوراً مع تيليجرام).
2. لينكدإن OAuth + اختيار الحساب/الصفحة.
3. Meta (فيسبوك + إنستغرام) + اختيار الصفحة.
4. X.
5. تبسيط الواجهة + وسوم الأنواع + تجربة النشر.
6. الدليل داخل الشاشة وفي `/guide` بثلاث لغات.
