# خطة: الإصلاح الفوري + الفحص المصغّر بالنماذج المختارة + ربط الرصيد وأنماط التشغيل بكل الأدوات

الشروط الصارمة: إضافة فقط — لا إعادة بناء، لا إعادة تسمية، لا حذف، لا تغيير لمنطق أي أداة قائمة. أي خطأ في الطبقات الجديدة يُعيد الأداة لسلوكها الحالي. لا نشر قبل موافقتك.

## 1) الإصلاح الفوري (بعد التحليل)
- زر «أصلح ليتوافق مع GEO» تحت نتيجة التحليل: يعيد صياغة أول 120–150 كلمة بكثافة حقائق، دون اختلاق أرقام (يستخدم فقط ما في النص الأصلي).
- زر «ولّد ملفات قراءة الآلة»: ينتج llms.txt و JSON-LD (Organization/FAQ) جاهزة للنسخ والتنزيل، من بيانات النتيجة وبطاقة سلطة العلامة إن وُجدت.
- كل زر يُخصم من الرصيد كعملية مستقلة بسعر تحدده الإدارة.

## 2) الفحص المصغّر (Micro-Probe) باختيار النماذج
- بعد أي تقدير خوارزمي، يظهر خيار «تحقق فعلياً من النماذج».
- المستخدم يختار: كل النماذج التسعة، أو عدداً محدداً منها بالضغط على الشعارات.
- قبل التشغيل تظهر الكلفة المتوقعة = سعر كل نموذج × عدد النماذج المختارة، مع الرصيد المتبقي. إذا لم يكفِ الرصيد يُعطَّل الزر مع توضيح.
- النماذج غير المتاحة في باقة المستخدم تظهر مقفلة (الحد الحالي حسب الباقة يبقى كما هو).
- النتيجة تظهر بنفس بطاقات النماذج المتحركة بوسم «إجابة فعلية»، بجانب التقدير السابق، مع الفارق بينهما (يُسجَّل لتحسين دقة الخوارزمية لاحقاً).

## 3) الرصيد مرتبط بكل الأدوات
- كل أداة وكل عملية فرعية (فحص مصغّر، إصلاح، توليد ملفات، تحديث إجباري) تمر بنظام الخصم الحالي نفسه.
- شريط صغير قبل التشغيل في كل أداة: «الكلفة المتوقعة / رصيدك».
- الأداة غير المسعّرة تبقى كما هي اليوم (رسالة «لم تُسعَّر»)، ويظهر للإدارة في كاشف فجوات التسعير.

## 4) أنماط التشغيل لكل مستخدم
لكل أداة يختار المستخدم أحد ثلاثة أنماط:
- **فوري**: كما اليوم.
- **في الخلفية**: يبدأ العمل ويستطيع المستخدم مغادرة الصفحة، والنتيجة تُحفظ في سجل الأداة.
- **إشعاري**: يعمل في الخلفية ويُرسل إشعاراً (داخل المنصة، ويمكن البريد) عند الانتهاء.
- خيار «تلقائي مجدول» للأدوات التي تقبل التكرار (المراقبة، الظهور، MKD) — يعتمد على الجدولة الموجودة، ويخصم من الرصيد عند كل تشغيل مع إيقاف تلقائي عند نفاد الرصيد.

## 5) تحكم الإدارة
لوحة واحدة جديدة داخل قسم التوكنز (دون المساس باللوحات الحالية):
- لكل أداة: السعر، تفعيل/تعطيل، الأنماط المسموحة (فوري/خلفية/إشعاري/مجدول)، سعر كل نموذج في الفحص المصغّر، الحد الأقصى للنماذج.
- لكل مستخدم: تجاوز أي من القيم السابقة لكل أداة، حد يومي/شهري خاص بالأداة، إيقاف النمط المجدول.
- عرض استهلاك كل مستخدم لكل أداة ولكل عملية فرعية.

## ترتيب التنفيذ
1. توسيع إعدادات التسعير والأنماط (الإدارة) + شريط الكلفة.
2. الفحص المصغّر باختيار النماذج.
3. الإصلاح الفوري وتوليد llms.txt/JSON-LD.
4. أنماط الخلفية/الإشعاري/المجدول.
5. اختبارات + فحص في المتصفح + تحديث الأدلة.

## تفاصيل تقنية
- إعادة استخدام `resolveToolCost` / `chargeTokens` / دالة `charge_tokens`: العمليات الفرعية بمفاتيح مثل `analyze.probe`, `analyze.fix`, `analyze.machine_files`؛ الفحص المصغّر يخصم `probe` × عدد النماذج في استدعاء واحد (tokens مضروبة) مع meta بأسماء النماذج.
- اختيار النماذج يمر عبر `applyEntitlement` الحالي، ثم `callGateway`/`ai-engines.server.ts`؛ الفحص يُنفّذ بمسار جديد `src/routes/api/probe.ts` (مصادقة Bearer) دون تعديل المسارات القائمة.
- تجاوزات المستخدم تُخزّن في `per_user_tool_overrides` الموجود (حقول إضافية: `modes`, `probe_tokens_per_engine`, `max_engines`, `daily_cap`)؛ إعدادات الأداة العامة في `tool_plan_access` + `app_settings` (`tool_run_modes`). لا جداول جديدة إلا جدول مهام خلفية واحد `tool_jobs` (user_id, tool_key, mode, status, input, result, notify) مع RLS للمالك والإدارة إن لم يكفِ `hermes_tasks`/`maaroof_schedules` بعد الفحص.
- الخلفية/الإشعار: مهمة تُسجّل ثم تُنفّذ عبر مسار خادم وتكتب النتيجة في `report_drafts` و `user_notifications`؛ المجدول يعيد استخدام `maaroof_schedules`.
- الواجهة: مكوّنات جديدة `EnginePicker`, `CostPreview`, `RunModeSelect`, `GeoFixPanel` تُضاف أسفل النتائج فقط.
- اختبارات vitest للكلفة واختيار النماذج والمحوّلات؛ تحديث `AGENTS.md` و `docs/MCI_AUDIT.md`.
