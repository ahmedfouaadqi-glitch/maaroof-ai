# تشغيل Firecrawl و API Direct معاً بتناغم

## الهدف
أن تعمل أدوات البحث والزحف (البحث الذكي، فحص النماذج العشرة، المتصفح الآمن، الفحص العميق، المعرفة) دون أي تعليق، وأن يُكمل كل منهما الآخر بدل أن يتوقف الفحص عند تعطّل أحدهما.

## ترتيب العمل لكل طلب
```text
رابط لينكدإن        -> API Direct (مسار LinkedIn) -> Firecrawl -> تخطٍّ آمن
موقع/صفحة عامة      -> Firecrawl -> قراءة مباشرة للصفحة -> تخطٍّ آمن
بحث ويب             -> Firecrawl -> بحث API Direct -> "غير متاح، لم يُخصم شيء"
```
- مهلة 15 ثانية لكل محاولة؛ عند انتهائها ينتقل فوراً للمصدر التالي.
- لا يُخترع أي محتوى أو رابط: الروابط المعروضة هي فقط ما أعاده مصدر حقيقي.
- الخصم يبقى كما هو: فقط عند النجاح.

## الخطوات
1. حفظ مفتاح API Direct بأمان في إعدادات المشروع (نافذة آمنة تطلبه منك مرة أخرى؛ لن يُستخدم النص الملصق في المحادثة). يُنصح بتدوير المفتاح لاحقاً لأنه ظهر في المحادثة.
2. التحقق من أن Firecrawl يعمل بعد الشحن بطلب بسيط واحد.
3. إضافة طبقة موحّدة للجلب تطبّق الترتيب أعلاه، وتستخدمها كل الأدوات الحالية دون تغيير منطقها.
4. إصلاح الفحص العميق: إلغاء المهمة العالقة `1abf0bf2`، وتطبيق المهلة والتخطي الآمن لكل رابط بحيث تكتمل النتيجة حتى لو فشل رابط.
5. إظهار مصدر القراءة بلغة بسيطة في سجل البطاقة (مثل «قُرئ مباشرة» / «لم تُقرأ الصفحة») دون ذكر أسماء المزودين.
6. اختبارات لقواعد الترتيب والمهلة وعدم الخصم عند الفشل، ثم تشغيل فحص عميق حقيقي على حسابك للتأكد من قراءة الموقع ولينكدإن.

## تفاصيل تقنية
- ملف جديد `src/lib/fetch-chain.server.ts`: `scrapeWithFallback(url)` و`searchWithFallback(q)` بـ AbortController (15s)، يعيدان `{ok, markdown, metadata, source}` بنفس شكل مخرجات `fcScrape/fcSearch`.
- `src/lib/apidirect.server.ts`: `GET /v1/linkedin/person|company?url=` و`GET /v1/web/search?query=` بترويسة `X-API-Key` من `process.env.APIDIRECT_API_KEY`؛ توحيد الاستجابة.
- قواعد الترتيب نقية في `src/lib/fetch-order.ts` مع اختبار.
- استبدال الاستدعاءات في `deep-audit.ts`, `research.ts`, `visibility.ts` (مسار الأدلة), `knowledge-enrich.server.ts`, `teaching-web.server.ts`, المتصفح الآمن.
- سجل القرار في `AGENTS.md`.
