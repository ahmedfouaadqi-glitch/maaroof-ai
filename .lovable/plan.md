# الموجة الثالثة — الأجزاء 14 إلى 17

تُبنى فوق ما هو قائم فعلاً (تطوير لا استبدال): قنوات النشر `publish_channels` وسجل `publish_log` والموافقات في `agent_tasks`، ومحرّك الثقة الحالي داخل `orchestrator.server.ts`، وسجل القرار `decision_traces`، ومركز الذكاء الإداري الموحّد. لا تُنشأ لوحة إدارة جديدة منفصلة؛ تُضاف أقسام داخل نفس المركز.

## الجزء 14 — منظومة النشر التنفيذية

- **طبقة قدرات نشر مستقلة**: `src/lib/maaroof/publishing.server.ts` تسجّل كل وجهة (Facebook، Instagram، LinkedIn، X، TikTok، Telegram، WhatsApp، Google Business، WordPress، Medium، Reddit، Discord، Slack، Email، RSS، Webhook، MCP) بملف منصة مستقل: الجمهور، أفضل وقت، حدود المحتوى، قواعد المخاطر. الوكيل لا يلمس أي منصة مباشرة — ينتج **استراتيجية نشر** فقط.
- **جداول جديدة**: `publishing_platforms` (ملف كل منصة + قابلة للتوسع)، `publishing_campaigns`، `publications` (المحتوى + المرحلة من Idea حتى Learning + التكلفة)، `publication_metrics` (وصول، نقرات، تفاعل، إشارات ظهور).
- **مسار العمل**: فكرة ← تخطيط ← مجلس خبراء (يُعاد استخدام محرّك الخبراء الحالي) ← مراجعة علامة وامتثال ← تكلفة ← موافقة ← جدولة ← نشر ← قياس ← تعلّم يغذّي الذاكرة والمعرفة.
- **الموافقات**: أنماط (سؤال دائم / موافقة مرة / موافقة حملة / سياسة مساحة عمل / تلقائي كامل / إيقاف طارئ) على مستوى كل Workspace، مبنية فوق `approval_mode` الموجود في القنوات.
- **الواجهة**: قسم «مركز النشر» داخل مركز الذكاء: حملات، منصات، موافقات، جداول، سجل، تكاليف، تحليلات، توصيات، وكلاء فرعيون. تصدير PDF/Excel/CSV/Markdown/JSON بثلاث لغات.

## الجزء 15 — هندسة الثقة التنفيذية

- **ترقية محرّك الثقة الحالي** إلى محرّك مستقل `trust.server.ts` يمرّ بخط: المصدر ← الدليل ← الاستدلال ← المعرفة ← الخبير ← النموذج ← تاريخ التنفيذ ← سياق العمل ← محاكاة المستقبل ← المخاطر ← تقييم الثقة ← التوصية.
- **جدول `trust_profiles`**: ملف ثقة ديناميكي لكل كيان (خبير، نموذج، MCP، عقدة معرفة، وكيل، مساحة عمل، أداة) بدرجات تتغيّر بعد كل تنفيذ ونتيجة أعمال.
- **درجة القرار التنفيذي**: قيمة أعمال، أثر مستقبلي، أثر مالي، ثقة، بدائل، مخاطر، إمكانية تراجع، عائد تقديري — تُضاف فوق `decision_traces`.
- **قسم «مركز الثقة»**: تطوّر الثقة، ترتيب الخبراء والنماذج و MCP والمعرفة، تحليل التناقض، دقة التنبؤ، تحليل الإخفاق والنجاح، شرح كامل لكل توصية.

## الجزء 16 — مرساة الحالة الحيّة

- **`state.server.ts` + جدولا `state_anchors` و`state_timeline`**: مراسي متعددة المستويات (منصة، مساحة عمل، مستخدم، جلسة، تشغيل، وكيل فرعي، خبير، مهمة) بوراثة من الأب ومنع مخالفته.
- **التحقق قبل التنفيذ**: الهوية، المهمة، السياسات، الميزانية، القدرات — قبل أي تشغيل في المنسّق.
- **كشف الانحراف (Drift)**: هدف، معرفة، ذاكرة، استدلال، سياسة، نموذج، ثقة، لغة — مع شرح وقياس واقتراح تصحيح.
- **الاسترجاع**: عند فشل التنفيذ يُستأنف من آخر حالة سليمة بدل إعادة البدء من الصفر.
- **قسم «مركز الحالة»**: حالة كل مستوى، الجدول الزمني، تقارير الانحراف، سجل الاسترجاع والتراجع، درجة صحة الحالة.

## الجزء 17 — هيرمس، الوكيل التنفيذي للمؤسس

- **كيان مراقبة فقط** — لا ينفّذ ولا يعدّل أي شيء: `hermes.server.ts` + جدولا `hermes_proposals` و`founder_dna`.
- **المرصد**: يراقب المعمارية والمعرفة والثقة والحالة والنماذج و MCP والتكاليف والإيرادات والمستخدمين ومؤشرات الأعمال.
- **المقترحات التنفيذية**: ملخص، مشكلة، دليل، قيمة أعمال، تحليل تقني ومالي ومخاطر، بدائل، خطة تراجع، عائد وتوكنات وزمن تقديري. يُرفض أي مقترح آلياً إذا كانت القيمة المتوقعة أقل من التكلفة.
- **صندوق المؤسس**: موافقة/رفض/تعديل/تأجيل/أرشفة — وكل قرار (قبولاً أو رفضاً) يُثري «حمض المؤسس» الذي يوجّه المقترحات اللاحقة.
- **مكتب هيرمس**: قسم إداري للمحادثة الطبيعية بالعربية والإنجليزية والكردية، بإجابات مسنودة بالأدلة والأرقام، مع كشّاف مستقبلي للنماذج والمنصات والاتجاهات الجديدة.

## ملاحظات تقنية

- ترحيلات قاعدة البيانات على دفعتين: (أ) النشر + الثقة، (ب) الحالة + هيرمس — كل جدول مع صلاحيات صريحة وسياسات وصول تقصر البيانات على صاحبها والإدارة.
- كل محرّك جديد خلف مفتاح تشغيل في إعدادات معروف؛ عند الإطفاء يعود السلوك حرفياً إلى ما هو عليه اليوم.
- لا نداءات نموذج إضافية في الثقة والحالة وهيرمس إلا عند الطلب الصريح — الحسابات محلية لتفادي أي تكلفة مخفية، وأي تكلفة تعلّم تُقيَّد على ميزانية النظام لا على رصيد المستخدمين.
- الأقسام الأربعة تُضاف داخل `MaaroofIntelligenceCenter` ضمن مجموعتين جديدتين: «execution» و«stewardship».
