# ربط كل الأدوات بالرصيد فقط + إصلاح توقف الفحص العميق + تأكيد الأسواق

## 1. الرصيد هو الحاكم الوحيد
- إزالة شرط "200 تحليل شهرياً" القديم من الأدوات الـ14: what-if, visibility, suggest, social-analysis, competitor-monitor, compare, brand-boost, brand-authority, bizdev, applied-ranking, feasibility, geo-strategist, geo-rewrite, analyze.
- تبقى عملية الخصم الموحدة كما هي (خصم بعد النجاح، استرجاع عند الفشل).
- يبقى عدّاد التحليلات للإحصاء فقط ولا يمنع أي تنفيذ.
- اختبار: أداة لا تُرفض عندما يكون العدّاد فوق 200 والرصيد كافٍ، وتُرفض فقط عند نقص الرصيد.

## 2. المرفقات
- تحليل المرفق يُخصم من الرصيد فقط بعد النجاح، مع مهلة محددة ورسالة واضحة عند تعذّر القراءة بدون خصم.

## 3. الفحص العميق والمهام لا تتوقف
- إرسال حدث "بدأ الفحص" فوراً عند الإنشاء، وانتظار تأكيده (حتى 3 ثوانٍ) قبل إعادة رقم المهمة — نفس ما يعمل الآن في المهام.
- نبضة تقدّم قبل وبعد كل رابط، ومهلة 15 ثانية لكل رابط عبر ترتيب المصادر (API Direct ← Firecrawl ← قراءة مباشرة)، وتخطّي الرابط المتعثر بدون خصم.
- نفس الحماية لفحص الظهور (visibility) الذي يعمل في الخلفية.
- زر "إعادة المحاولة" على بطاقة المهمة الفاشلة يستأنف دون إعادة خصم الأدوات الناجحة.

## 4. الأسواق في بطاقة الكيان
- البطاقة تقرأ أسماء الأسواق الموثّقة: "مؤكد بالدليل" / "مؤكد من المالك" / "غير مؤكد".
- الفحص العميق ومجلس النماذج العشرة يستخدمان الأسواق المؤكدة فقط.
- النشر في البيانات المهيكلة وllms.txt يبقى بعد موافقتك فقط.

## تفاصيل تقنية
- حذف كتلة `monthly_analyses_used >= limit` من كل مسار مع إبقاء `chargeTokens`.
- `deep-audit.ts`: `emit("audit_start")` قبل `runAfterResponse` + انتظار أول حدث، `touch updated_at` لكل هدف، `Promise.race` بمهلة 15s.
- `visibility.ts`: نفس مصافحة البدء.
- `workspace.tsx`: زر Retry يستدعي الاستئناف عبر `reusableResults`.
- `verifyEntityCard` + `EntityFields.tsx` يقرآن `entity_market_names` عبر `marketStatus`.
- اختبارات في `src/lib/__tests__/` لقاعدة الرصيد وحالة الأسواق.
