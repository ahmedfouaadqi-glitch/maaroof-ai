## الهدف
إعادة بناء أداة مقارنة المنافسين بحيث لا تعتمد على تقدير واحد عام، بل تجمع أدلة حقيقية لكل علامة، تكتشف الموقع الرسمي بدقة أكبر، وتنتج درجات المنصات الثمانية من قياسات مباشرة/شبه مباشرة مع شفافية حول مصدر كل درجة.

## المشكلة الحالية
- الأداة تبحث عبر Firecrawl ثم تختار موقعاً رسمياً بمنطق مطابقة ضعيف، خصوصاً مع الأسماء العربية أو العلامات التي لا يظهر اسمها حرفياً في الدومين.
- درجات المنصات الثمانية حالياً “مستنتجة” من عدد المصادر وإشارات SEO فقط، وليست قياساً حقيقياً لكل منصة.
- تم تعطيل `platform-probe.server.ts` فعلياً، لذلك لم تعد هناك طبقة فحص للمنصات كما كانت سابقاً.
- نقاط القوة والضعف أصبحت مفيدة تقنياً لكنها قد لا تمثل ظهور العلامة الحقيقي على كل منصة.

## الحل الجذري المقترح

### 1. إنشاء محرك أدلة موحّد لكل علامة
- بناء دوال منفصلة داخل `src/routes/api/compare.ts` أو ملف مساعد جديد مثل `src/lib/competitor-evidence.server.ts`.
- لكل علامة يتم جمع الأدلة من:
  - بحث الموقع الرسمي.
  - بحث عام باسم العلامة + المجال + السوق.
  - الأخبار.
  - التقييمات/المراجعات.
  - التواجد المحلي/العنوان.
  - نتائج باللغة العربية والإنجليزية عند الحاجة.
- إزالة التكرارات، ترتيب المصادر حسب الجودة، وتخزين نوع كل مصدر.

### 2. تحسين اكتشاف الموقع الرسمي بآلية scoring بدلاً من اختيار أول نتيجة
- تقييم كل URL مرشح وفق نقاط:
  - الدومين يشبه اسم العلامة أو ترجمتها/تهجئتها.
  - العنوان والوصف والمحتوى يذكر العلامة.
  - الموقع ليس سوشيال/دليل/خبر/متجر عام.
  - وجود صفحات about/contact/products/services.
  - وجود بيانات منظمة Organization/LocalBusiness.
- إذا أعطى المستخدم رابطاً، يتم استخدامه كمرشح قوي لكن مع فحصه، لا تجاهله ولا قبوله أعمى.
- إرجاع `official_site_status`: confirmed / candidate / missing حتى يعرف المستخدم مدى الثقة.

### 3. إعادة تفعيل فحص المنصات الثمانية بطريقة أكثر واقعية
- إعادة استخدام `src/lib/platform-probe.server.ts` ولكن بصيغة جديدة:
  - ليس مجرد تخمين من ملخص الأدلة.
  - لكل منصة يتم إنشاء “استعلام اختبار” مخصص يحاكي كيف يمكن أن تُسأل المنصة عن العلامة والمنافسين.
  - استخدام Lovable AI بنداء أقوى واحد أو نداءين كحد أقصى عندما يريد المستخدم الجودة حتى لو كانت مكلفة.
  - النموذج يعيد: هل العلامة قابلة للذكر، درجة الظهور، سبب الدرجة، الأدلة المستخدمة، وما الإشارة الناقصة.
- لأننا لا نملك API مباشر لكل منصة خارج Lovable AI، سنسمي النتائج بوضوح: “محاكاة ظهور مبنية على الأدلة” لا “قياس مباشر داخل حساب ChatGPT/Claude”.

### 4. نمطين للتكلفة داخل الأداة
- إضافة خيار في الواجهة:
  - “اقتصادي”: Firecrawl + نموذج واحد خفيف.
  - “دقيق”: بحث أوسع + نموذج أقوى + فحص منصات أكثر تفصيلاً.
- بما أن طلبك الحالي يقول “حتى وإن كان مكلفاً”، يكون الوضع الافتراضي لهذه الأداة بعد الإصلاح هو “دقيق”، مع إبقاء الاقتصادي لمن يريد تقليل الرصيد لاحقاً.

### 5. استخدام Semrush عندما تتوفر الدومينات
- عند اكتشاف موقع رسمي للعلامة والمنافس، يمكن جلب مؤشرات SEO حقيقية من Semrush للأدلة التالية:
  - الزيارات العضوية التقديرية.
  - عدد الكلمات المفتاحية.
  - أفضل الصفحات.
  - مقارنة دومينين عند وجود علامة ومنافس واحد.
- هذه البيانات تعزز الدرجات ولا تستبدل Firecrawl، لأنها تعمل فقط عند توفر دومين صالح.
- إذا لم تنجح Semrush أو لم تكن مناسبة للسوق، تستمر الأداة بدون فشل.

### 6. إعادة حساب الدرجات النهائية بشفافية
- لكل علامة يتم حساب:
  - `visibility_percent`: خليط من مصادر البحث، قوة الدومين/SEO، الموقع الرسمي، ونتائج محاكاة المنصات.
  - `geo_score`: تركيز على SEO/SGE والمحتوى المحلي والتواجد الجغرافي.
  - `platform_presence`: 8 درجات مع `basis` لكل منصة: measured_simulation / evidence_inferred / insufficient_evidence.
- لا تظهر أرقام عالية إذا لم توجد أدلة كافية.

### 7. نقاط قوة وضعف حقيقية ومفسّرة
- كل نقطة قوة/ضعف سيتم ربطها بسبب محدد:
  - موقع رسمي مؤكد/غير مؤكد.
  - Schema موجود/ناقص.
  - أخبار كافية/غير موجودة.
  - مراجعات وتواجد محلي قوي/ضعيف.
  - ضعف محتوى طويل أو FAQ أو روابط خارجية.
  - ضعف خاص بمنصة معينة مثل Perplexity يحتاج مصادر حديثة، أو Gemini يحتاج Schema/LocalBusiness.

### 8. تحديث الواجهة
- عرض حالة الموقع الرسمي لكل علامة.
- عرض نوع درجة كل منصة: محاكاة مبنية على الأدلة / مستنتجة / أدلة غير كافية.
- عرض مصدر أهم 3 إشارات أثرت في كل علامة.
- إبقاء قائمة المصادر الحالية، لكن ترتيبها حسب العلامة والنوع والثقة.

## الملفات التي سيتم تعديلها
- `src/routes/api/compare.ts`
  - إعادة تنظيم جمع الأدلة، اكتشاف الموقع الرسمي، حساب الدرجات، واستدعاء Lovable AI/Semrush.
- `src/lib/platform-probe.server.ts`
  - تحويله إلى فاحص منصات حقيقي مبني على أدلة واستعلامات اختبار، بدل أن يكون معطلاً أو مجرد تقدير مبسط.
- `src/lib/seo-sge.server.ts`
  - تحسين أوزان الدرجات ونقاط القوة/الضعف، وإضافة أسباب قابلة للعرض.
- `src/components/CompetitorCompare.tsx`
  - إضافة خيار الدقة/التكلفة، وعرض حالة الموقع الرسمي ومصدر درجات المنصات.
- `src/lib/i18n.tsx`
  - إضافة الترجمات العربية/الإنجليزية/الكردية للنصوص الجديدة.

## ملاحظات مهمة
- لا يمكن الوصول مباشرة إلى قواعد بيانات ChatGPT وClaude وGrok وغيرها كما لو أنها APIs رسمية للبحث داخل كل منصة. الحل الواقعي هو محاكاة دقيقة ومعللة باستخدام الأدلة العامة الحقيقية + Lovable AI، مع تسمية ذلك بوضوح.
- بما أن Firecrawl وLovable AI موجودان بالفعل، لن أطلب منك مفاتيح جديدة.
- Semrush متاح كأداة تحسين SEO أثناء البناء، وسأستخدمه في المنطق عندما توجد دومينات، بدون إلزام المستخدم بإدخال مفاتيح.

## نتيجة التنفيذ المتوقعة
عند إدخال اسم علامة ومنافس فقط، ستحاول الأداة اكتشاف الدومينات الرسمية، تجمع مصادر حقيقية، تحلل SEO/SGE، ثم تعطي درجات المنصات الثمانية ونقاط القوة/الضعف بناءً على الأدلة، مع توضيح الثقة ومصدر كل نتيجة بدلاً من أرقام عامة أو وهمية.
