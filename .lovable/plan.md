## الهدف
تعزيز أداة "تعزيز العلامة التجارية في منصات الذكاء" بثلاث طبقات: (١) دليل وأزرار مشاركة في تبويب السلطة، (٢) متتبع انتشار موجَّه وقابل للفهم، (٣) صفحة شخصية عامة لكل مستخدم على نطاقنا تقرؤها العناكب وتُربط بالمتتبع، مع تفعيل السجل والتصدير في كل التبويبات.

استخدمت الشكل `https://geoiraq.com/u/{username}` لأنه قصير وثابت ومألوف.

---

## ١. تبويب "محرك السلطة" (UI فقط)
**في `src/components/BrandBoostAgent.tsx` (أو الملف الذي يحتوي تبويب Authority)**
- بعد توليد رابط السلطة، إظهار:
  - شريط خطوات مرقّم بالعربي/الكردي/الإنجليزي: "افتح ← انسخ ← شارك ← راقب التتبع"
  - صف أزرار مشاركة سريعة: WhatsApp · X · LinkedIn · Facebook · Telegram · نسخ الرابط · فتح في تبويب جديد
  - بطاقة "ماذا يحدث الآن؟" تشرح أن العناكب ستبدأ بالزيارة خلال ساعات إلى أيام بعد المشاركة
- أزرار التصدير: JSON · Markdown · نسخ JSON-LD

---

## ٢. تبويب "متتبع الانتشار" (UI + استعلام)
**في نفس المكوّن**
- إذا كانت `crawler_hits` فارغة: بطاقة إرشادية مع زر "اذهب لمشاركة الرابط" يعود لتبويب السلطة
- جدول الزيارات: يعرض زيارات `/api/public/brand/*` **و** `/u/*` (المسار الجديد)
- شرح كل اسم عنكبوت بالعربي (GPTBot = ChatGPT, PerplexityBot = Perplexity…)
- زر "تصدير CSV" لكامل الزيارات
- زر "تحديث" يدوي

---

## ٣. صفحات المستخدمين العامة `/u/{username}`
### ٣.أ — قاعدة البيانات (Migration)
- إضافة عمود `username TEXT UNIQUE` على `profiles` (nullable + قيد طول 3–32 + regex `^[a-z0-9_-]+$`)
- تحديث trigger `handle_new_user` ليُولِّد `username` تلقائيًا من البريد (مع لاحقة رقمية عند التعارض)
- سياسة RLS قراءة عامة محدودة على `profiles` فقط للأعمدة `(id, username, full_name, brand_name, brand_keywords)` — أو الأفضل: عدم فتح RLS عام، واستخدام `supabaseAdmin` داخل المسار العام مع `SELECT` مقيد على الأعمدة الآمنة فقط (لا بريد، لا اشتراك، لا fingerprints)

### ٣.ب — مسار عام جديد `src/routes/u.$username.ts`
- TSS server route يُعيد HTML قابل للفهرسة:
  - `<title>`, `<meta description>`, JSON-LD من نوع `Person` أو `Organization`
  - عرض اسم العلامة + الكلمات المفتاحية + قائمة بكل بطاقات السلطة الخاصة بالمستخدم (روابط لـ `/api/public/brand/{slug}`)
  - `<link rel="canonical">`، `X-Robots-Tag: index, follow`
- يسجّل زيارة كل عنكبوت في `crawler_hits` بـ `path = /u/{username}` و `brand_slug = ""` و `user_id` المالك (نفس آلية `brand/$slug.ts`)

### ٣.ج — تحديث Sitemap
**في `src/routes/sitemap[.]xml.ts`**
- إضافة استعلام يجلب كل `profiles.username` غير الفارغة ويُدرج `/u/{username}` كمدخلات سايتماب

### ٣.د — صفحة Profile للمستخدم
**في `src/routes/profile.tsx`**
- قسم جديد "صفحتك العامة": يعرض الرابط `https://geoiraq.com/u/{username}` + أزرار نسخ/فتح/مشاركة
- حقل تعديل `username` (مع تحقق فوري من التوفر)

---

## ٤. سجل النشاط داخل الأداة
- تبويب فرعي "السجل" أعلى الأداة يقرأ آخر 50 سطرًا من `activity_log` للمستخدم الحالي حيث `action IN ('brand_boost','brand_authority')`
- جدول: التاريخ · النوع · العلامة · ملخّص النتيجة
- زر "تصدير CSV"

---

## ٥. التصدير الموحَّد
إضافة مكوّن `<ExportButtons>` (موجود مسبقًا) في كل تبويب: CSV + JSON. زر "طباعة" حيث يكون منطقيًا.

---

## تفاصيل تقنية مختصرة
- **الترتيب**: تنفيذ Migration أولًا → ثم المسار `/u/{username}` → ثم تحديث Sitemap → ثم UI (تبويبات + سجل + تصدير) → ثم أزرار المشاركة
- **الأمان**: المسار `/u/*` يستخدم `supabaseAdmin` مع SELECT صريح للأعمدة الآمنة فقط (لا تسرّب PII). تحقق طول `username` و regex قبل أي استعلام.
- **i18n**: كل النصوص الجديدة تمر عبر `useI18n()` بالعربي/الكردي/الإنجليزي
- **التوافق**: لا تعديل على `client.ts` / `types.ts` (تتجدد تلقائيًا بعد Migration)
- **بدون تغيير منطق**: لن تُمَس منطق توليد البطاقات أو حسابات الحصص — فقط واجهة + مسار عام + سايتماب + سجل
