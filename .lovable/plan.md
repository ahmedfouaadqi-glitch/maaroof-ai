# ربط طبقة الإسكندرية عبر Firecrawl

## الهدف
تشغيل الإسكندرية فعلياً داخل «النتيجة الثانية» باستخدام مفتاح Firecrawl الموجود، مع اكتشاف القدرات أولاً، واستدعاء ما أعاده الاكتشاف فقط، وعرض تكلفة كل استدعاء.

## ما سيحدث
1. **الاكتشاف أولاً**: لكل مهمة يبحث النظام في كتالوج الإسكندرية عن قدرات تناسب العلامة والمنافسين والسوق (بيانات الشركات، الحضور الرقمي، الأخبار).
2. **الاستدعاء المقيد**: لا يستدعي إلا قدرة ظهرت في نتيجة الاكتشاف نفسها، بحد أقصى 3 استدعاءات لكل سوق.
3. **التكلفة الحقيقية**: تُسجَّل الكريديت التي أعادتها Firecrawl لكل استدعاء وتظهر في الدردشة وفي ورقة «خطة التنفيذ».
4. **الرصيد الموحد**: يُخصم من رصيدك فقط عند نجاح الاستدعاء (`alexandria.call`، يرتد لسعر الأداة الأم).
5. **بلا بدائل مختلقة**: إذا لم يجد الاكتشاف قدرة مناسبة أو فشل الاستدعاء، تظهر «لم تُعد الإسكندرية بيانات» مع السبب.
6. **الأدلة**: تدخل السجلات كمصدر موسوم «Alexandria / المزود / القدرة» في المصنف وبطاقة المقارنة.

## التفاصيل التقنية
- `src/lib/alexandria.server.ts`: `discover(query)` عبر `POST /v2/search` بمصدر alexandria، و`retrieve(provider, capability, options)` عبر `POST /v2/scrape` بصيغة alexandria؛ يحترم وضع المفتاح (`fc-` مباشر أو `lovc_` عبر البوابة) ومهلة لكل محاولة.
- قاعدة نقية `src/lib/alexandria-policy.ts`: تسمح فقط بقدرة موجودة في نتيجة الاكتشاف + حد الاستدعاءات؛ مع اختبارات.
- استبدال `gatherAlexandria` الحالي (المعتمد على `ALEXANDRIA_API_URL`) بهذا المسار، مع إبقاء حالة «غير متصلة» عند غياب المفتاح.
- `dual-result.ts` و`operational-workbook.ts`: تمرير الأدلة والتكلفة وحالة الاتصال الحقيقية.
- تسجيل القاعدة في `AGENTS.md`.
