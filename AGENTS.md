- MCI (Context Intelligence) lives in src/lib/mci/: registry + fail-open resolver run before tools; additive only, never changes tool logic — why: cut repeat AI/web calls safely.

- MCI Foundation modules (types, canonical-entity, budget, freshness, evidence gate, provenance, selector) are pure and exported via src/lib/mci/index.ts; not yet wired into tools — why: review before integration.
- Router uses intent preloading — why: faster navigation; heavy libs stay lazy.
- MCI tool reuse goes through mciReuse/mciStore in src/lib/mci/resolver.server.ts, called at the start/end of a tool route only — why: one fail-open, user-scoped cache path that never alters tool logic.
- Dashboard tool UIs are React.lazy + Suspense; nine-engine cards for non-engine tools come from pure adapters in src/lib/engine-card-adapters.ts labelled estimated/recommended — why: faster dashboard and no fabricated live answers.
- Agent planning reads MCI hints via mciPlanningHints (read-only, fail-open); agent step cards use cardsForStep — why: fewer repeated steps without changing tool logic.
- Tool sub-operations (e.g. visibility.probe) charge via chargeTokens units/unitTokens and fall back to the parent tool price; probe policy lives in app_settings.tool_run_modes + per_user_tool_overrides.visibility — why: one balance system for every tool, no parallel pricing.
- Live probe background mode uses the Worker ctx.waitUntil exposed per request via AsyncLocalStorage (src/lib/request-ctx.server.ts, set in src/server.ts), falling back to awaiting inline — why: no job queue, and cloudflare:* imports break the build.
- Server functions are protected by createCsrfMiddleware filtered to serverFn only — why: block cross-site RPC without touching external webhook routes.

- Entity Truth Card fields live on profiles (entity_*, hq_country, target_markets); only server/admin may set verification/lock fields (trigger guard) and consistency checks are pure rules in src/lib/entity-consistency.ts — why: one zero-cost identity source for all tools.
- Engine catalog (src/lib/ai-engines.ts) is the single source for all AI engines, incl. proxied ones like Qwen — why: adding an engine propagates to every tool, agent and UI.
- Maaroof fills missing tool inputs via pure src/lib/maaroof/agent-input.ts (goal > workspace > Entity Truth Card) and emits a `clarify` event instead of calling a tool with a missing required field — why: no failed paid steps, user is asked instead.
- Tool tabs/fields/enums the agent may use live in data-only src/lib/tool-options.ts (read from each /api route body); planner sees them and executor drops invalid enums — why: correct options per tool without touching tool logic.
- Maaroof recommendation/simulation results are formatted by pure src/lib/maaroof/mode-report.ts and priced as maaroof.<mode> (falls back to maaroof price) — why: no raw JSON for users, every mode is a real charged run.
- Workspace tasks run as background jobs: /api/maaroof with interface_mode=workspace stores maaroof_jobs + maaroof_job_events and runs runMaaroof via runAfterResponse; /api/maaroof-jobs polls/cancels — why: survive page reloads without a queue service, same charging gate as the live stream.
- Deep account audit runs as a maaroof_jobs row with mode=deep_audit via /api/deep-audit; scoring is pure (scoreTarget) and billing charges only successful targets once at the end — why: reuse job infra, no charge on failure.
- Workspace hierarchy uses workspaces.space_kind (company/product/client) + parent_id; structure and per-plan space limits are pure rules in src/lib/space-structure.ts — why: one tree for companies, products and agency clients without new tables.
- Each skill's 7-part framework (goal, sources, plan, cost, evidence, output, next step) is derived by pure skillFramework() in skill-catalog.ts from its tools — why: one consistent description without per-skill copy drift.
- Delegated browser is a read-only, per-session grant (browser_grants/browser_steps) checked by pure rules in src/lib/delegated-browser.ts on every step — why: no access outside explicit, expiring user permission.
- Learned facts live in knowledge_facts (source, confidence, expires_at); written on job completion/attachment analysis and read fail-open into the planner via src/lib/knowledge-facts.ts — why: Maaroof reuses what it already knows without changing tool logic.
- Attachments go to the private task-files bucket under <userId>/ and are analyzed by /api/attachment-analyze, charged as attachment.analyze only on success — why: same balance system, no cross-user file access.
- When no skill is selected, skills come from pure inferSkills (src/lib/maaroof/skill-inference.ts) using only words/URLs in the task, with the matched words saved as the reason; only tools with a real route are forced into the plan — why: no guessing and no failed steps.
- Workspace task resume reuses successful tool_result outputs of an earlier owned job (reusableResults in src/lib/maaroof/jobs.ts); optional run_options (salvage/focused/parallel) are off by default and the route sends a 60s heartbeat — why: long runs stay alive and no tool is re-run or re-charged.
- Live ten-model probe rules (answer parsing, real-link matching, partial refund, agent cannot set background) are pure in src/lib/maaroof/probe-answer.ts; agent progress cards read only recorded events incl. `narration` — why: no empty answers counted, no invented links or progress.
- Six-axis keyword values are observations only: SEO = actual rank, GEO/SGEO = share of answering engines mentioning/citing the brand (any delivery route counts), GSEO = observed SEO∩GEO, AEO/SGE only from exposed answer-box/overview citations; otherwise null with a reason — why: no formulas or invented scores.
- Web reads/searches go through fcScrape/fcSearch in src/lib/firecrawl.ts, which apply the fallback order in pure src/lib/fetch-order.ts (Firecrawl, API Direct for LinkedIn/search, plain HTTP) with a per-attempt timeout — why: no tool hangs when one provider fails.
- Owner-confirmed market names: entity_market_names table; evidence_confirmed only set server-side (trigger). Jobs fail as not-started after 45s with no events — why: honest market proof, fast hang detection.
- Exports append a per-result links section and the machine-readable pack (llms.txt, Organization JSON-LD, FAQPage) built by pure src/lib/machine-pack.ts from profiles.onboarding + confirmed markets only — why: no invented facts, one explained pack in every format.
- Workspace UI is one surface «دردشة» (src/components/workspace/Dardasha.tsx): chat + file drop/paste, tasks start only via explicit approval (canStartTask) and run options are automatic (AUTO_RUN_OPTIONS in src/lib/maaroof/dardasha.ts) — why: no manual toggles, no task without consent.
- Ten-engine tool council tries OpenRouter per engine and falls back to the platform gateway with that engine's persona (withFallback in src/lib/maaroof/tool-council.ts); attachments accept any type, office files are unzipped with fflate, unreadable binaries are recorded without charge — why: 10/10 answers without fabrication.
- Spreadsheets (xlsx/csv/public Google Sheets) are read by pure src/lib/spreadsheet-reader.ts (+ .server.ts for unzip/fetch); the structure+digest is stored on task_attachments.structure and reused by chat (attachment_ids) and tasks — why: every sheet/row is read once, no re-charge, no 'file unavailable' answers.
- Second result (operational workbook) is built by pure src/lib/operational-workbook.ts from full file rows + recorded research (competitive-geo.server.ts: web pages + ten engines per market from market-scope.ts) via /api/dual-result, charged per answered market as competitive_geo.market (falls back to compare) — why: every cell carries its source, missing evidence stays "not available".
- Per-keyword engine match scores come from separate cluster questions (pure src/lib/keyword-clusters.ts, charged per answered cluster as competitive_geo.cluster after the market charge); unmeasured keywords read "not measured"; Alexandria is used only when ALEXANDRIA_API_URL is set — why: real scores, no fake zeros or substitute data.
- Keyword intelligence result is eight sections built by pure src/lib/keyword-intelligence.ts (served by /api/dual-result, file optional; without a file keywords come from pure site-keyword-extractor.ts on the brand page) — why: one simple export with evidence-only values.
- New keywords come only from literal phrases in ten-engine discovery answers (pure src/lib/keyword-discovery.ts, confirmed at 2+ engines, charged per answered call as keyword_intelligence.discovery); large files are measured via a stratified sample with a free estimate_only preview — why: no invented keywords, cost visible before spending.
- Direct tool routes check a supplied workspace_id via workspaceGuard (src/lib/workspace-guard.server.ts); the council primary route is capped at 8s before the gateway fallback — why: no cross-workspace runs, no hanging engines.
- Workspace visibility/social tools render the unified VisibilityIntelligence, prefilled from the selected workspace; its 3-sheet Excel (src/lib/visibility-workbook.ts), free official-site discovery (src/lib/site-discovery.ts, /api/site-discovery) and opt-in baseline comparison (src/lib/visibility-baseline.ts, brand_operations.is_baseline) are pure and evidence-only — why: one surface, no invented values.
- Full workspace isolation: tools never write brand identity onto profiles; workspaceGuard records the verified workspace per request (setActiveWorkspace) and getUserContext/MCI cache keys scope to it — why: client data never leaks into the main account or another space.
